# 实现缺陷更正：E1 正式版的两处调用缺陷（2026-10-07）

> 触发：外部评审指出 `e1_formal.py` 的调用口径可疑。本报告记录**独立复核**结果：
> 缺陷属实，且不止一处。数字均可用仓内 ledger 复算。
> 结论：**精度结论不受影响；成本结论受影响，需重跑重测。**

---

## 一、缺陷一：被丢弃的批量调用全额计费

`e1_formal.py`（修正前）第 164-188 行：

```python
gens = run_prompt_n(msgs, ..., n_multi)   # 批量跑满 n 次，全部记账
for g in gens: ledger.log(...)
if hasattr(item, "numbers"):              # Countdown 类
    gens = gens[:1]                       # 丢弃 n-1 条
    for k in range(1, n_multi):           # 再串行补 n-1 次
        g = adapter.generate(req); gens.append(g); ledger.log(...)
```

Countdown 类题目因此每次生成 `n + (n-1)` 次，其中 `n-1` 次（批量部分）被丢弃。
**被丢弃的调用已经过 provider 计费**（ledger 的 token 计数包含它们）。

### 复算证据（`results/e1f_*_ledger.json`，cd6 = 12 题）

| 臂 | 名义调用 | 实际调用 | 倍数 |
|---|---|---|---|
| off×1 / low×1 / high×1 / max×1 | 12 | 12 | 1.00 |
| low×2 / high×2 | 24 | 36 | 1.50 |
| low×4 / high×4 | 48 | **76** | **1.58** |
| off×4 | 48 | **81** | **1.69** |
| low×8 | 96 | **129** | **1.34** |
| off×8 | 96 | **136** | **1.42** |

cd7（6 题）同构：high×4/low×4 = 36/24 = 1.50，off×4 = 41/24 = 1.71。

**×1 臂不受影响**（循环 `range(1,1)` 不执行），所以受污染的是全部 ×2/×4/×8 臂。

## 二、缺陷二：off 臂的串行段实际开着思考

同一段里：

```python
thinking=effort is not None,   # effort 是臂名字符串，"off" 不是 None → True
```

`effort` 在此处是循环变量（值域 `"off" | "low" | "high" | "max"`），不是归一化后的 `None`。
因此 **off 臂的串行调用以 thinking=True（默认强度）运行**。

证据：`off×1` 的 reasoning_tokens = **0**（只有批量调用，thinking 正确关闭）；
`off×4` 的 reasoning_tokens = **182,047**（串行 3 次/题开着思考）。

这条比缺陷一更隐蔽：它意味着被引用为"零思考 × 4 路采样"的那条臂，
**实际上只有 1/4 的生成是零思考的**。

## 三、对结论的影响

| 结论 | 是否受影响 | 说明 |
|---|---|---|
| 各臂精度（off×4 = 1.00 等） | 不受影响 | 精度是投票结果，与调用次数无关 |
| "off×4 成本约为 high×4 的一半"（$0.4787 vs $1.0157） | **不受影响，且偏保守** | 记录成本是**真实账单**（含浪费）；修复后 off×4 会更便宜 |
| "早停省 17-53% 成本" | **不成立** | 17-53% 是**样本条数**的节省；实现缺陷使 ×4 臂多花约 58% 的调用 |
| "off×4 是零思考采样臂" | **表述不准确** | 其 3/4 生成开着思考（缺陷二） |
| "成本比 1×max 低 56%~78%"（README 旧句） | **错误且无出处** | 方向相反：max×1 $0.11 比 off×4 $0.48 便宜；已改写 |

## 四、修复

`experiments/e1_formal.py` 已改：

1. Countdown 类**跳过批量**，直接串行生成 + 早停；
2. `thinking=effort != "off"`（替代 `effort is not None`）。

离线模拟（12 题 × 4 臂、STOP_K=3）验证调用数：

| | 调用数 | 相对名义 |
|---|---|---|
| 修正前 | 84（实测 76） | 1.75×（实测 1.58×） |
| 修正后 | 36 | 0.75× |

即修复后早停**确实**省成本（约 25%），但**这个数字必须重跑才能写进结论**。
