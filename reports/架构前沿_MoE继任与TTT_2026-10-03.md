# 架构前沿 ｜ MoE 继任者与模块化编排的三层实现谱系（2026-10-03）

触发（master）：搜索比 MoE 更优的架构方式（升级方向、考虑全面）；姿态原则：mo-agent-harness 等先例是**知识来源**而非竞品，学习思路为先。

---

## 一、2026 架构图谱：四大阵营 + 两条正交轴

| 阵营 | 代表 | 核心思想 | 代价 |
|---|---|---|---|
| Transformer 主线 | GPT/Claude/Llama | 自注意力，表达力最大 | O(n²) + 全 KV |
| SSM/线性 RNN | Mamba-2、RWKV-7、RetNet、xLSTM | 线性复杂度，固定状态 | 召回损失 |
| 混合 | Jamba、Griffin、Zamba | SSM 层 + attention 层交替 | 两者的折中 |
| 稀疏/MoE | DeepSeek-V3（671B/37B）、Mixtral、Llama-4、Kimi K2 | 大参数小激活 | 显存 hungry |
| 正交轴 | DiT（diffusion）、TTT、长上下文算法 | 生成范式 / 推理时学习 | 各异 |

关键判断：**MoE 是 2026 的默认起点而非终点**。继任/并行方向按成熟度：MoD（深度路由）→ TTT（推理时学习）→ SSM 混合 → Diffusion LLM。

## 二、五个比 MoE 更前沿的方向（含与外挂系列的映射）

### 1. TTT（Test-Time Training）——与"冻结基座 + 附加模块"同构度最高 ⭐

- **TTT-E2E**（NVIDIA×Stanford，2026-01）：推理时更新参数。核心机制是**双轨存储**：static MLP 保留预训练知识 + dynamic MLP 捕捉当前上下文——**这就是"冻结基座 + 附加模块"模式在 transformer 内部的架构级实现**。128K 上下文达全注意力精度且快 2.7×
- **In-Place TTT**（2026-04）：**实验模型正是 Qwen3-4B**（与我们同款！）——MLP 末投影矩阵作为 fast weight 原位更新，drop-in 不改架构；文档边界重置 fast weights 防上下文泄漏；RULER 256K 外推有效
- **TTCD**（2026-08）：context distillation——长窗教师监督短窗学生的 fast weights，"学习该记住什么"（为未来效用分配记忆容量）
- **三层实现谱系**：同一思想（模块化 + 条件计算 + 持续学习）的三个实现层次：
  1. **prompt/API 级**（我们，黑盒可用）：知识以补遗文本注入，缓存在前缀
  2. **权重级推理**（TTT/In-Place TTT，开模型可 drop-in）：知识以 fast weight 更新
  3. **权重级训练**（MoE 原生 / 持续预训练）
  → 三层不是竞争关系，是**同一设计在不同访问权限下的实现**。我们的黑盒层是唯一不需要模型权重的层——也是最可移植、最可普及的层

### 2. Mixture of Depths（MoD）——E1 强度旋钮的架构级对应 ⭐

- 深度维度路由：每 token 决定"跳过哪些层"（MoE 是宽度路由，MoD 是深度路由）
- 90% 层可转 MoD 只掉 1.5% 性能，推理时间 -53%；但前沿模型未采用（推理成本红利近期才成为主矛盾）
- **映射**：思考外挂的 effort 旋钮 = 深度路由的 API 级对应（思考 token 数 = 计算深度）；MoD 文献的"token redundancy 因任务而异"与 E1 的"任务难度决定档位"同构

### 3. EMO（Emergent Modularity MoE）——批处理场景的先例

- AI2 提出：**document 级路由**（整个文档共享同一语义专家子集，如 coding/health），而非逐 token 路由
- **与我们 E1 的"同题多采样共享前缀"和批处理场景完全同构**——又一个"文献先例在我们下游"的确认

### 4. Fine-Grained + Shared + Sigmoid + Auxiliary-Loss-Free（DeepSeek V3 模式集）

- 512 个小专家（更锐利专业化）、shared expert（每 token 必激活）、per-expert sigmoid（多专家可同时高激活）、auxiliary-loss-free bias 调负载
- **外挂栈对照**：外挂模块多而小（fine-grained）、PPBExt-Knowledge 是 shared expert、DecisionCore 允许多外挂同时激活（sigmoid 语义）、负载均衡用运行时 bias

### 5. SSM/混合的缓存含义——跨架构风险与 CacheTiers 必要性

- SSM 没有传统 KV cache（固定状态压缩）→ **前缀缓存的机制在 SSM 架构上完全不同**
- DeepSeek 若未来转混合架构（BlackMamba 式），当前的前缀缓存行为会变——CacheTiers 的探测分层正是为此保留的架构保险（探测而非假设）

## 三、对三定律与外挂栈的影响评估

| 定律/组件 | 受架构演进影响 | 应对 |
|---|---|---|
| 滞后窗定律 | DeepSeek 现行为不变；SSM/TTT 架构下 KV 滞后窗语义改变 | CacheTiers 探测（已实现）+ 三定律标注"DeepSeek API 口径" |
| 块级匹配（64 tok） | 同上 | 同上 |
| 跨会话复用 | TTT 类架构下"缓存"变成权重（持久化更强） | 正面：TTT 是跨会话复用的更强形式 |
| warmup 预热 | MoE 的专家预热（dummy token 触发全部 expert）已同构 | 已实现 |
| fine-grained 原则 | DeepSeek 512 专家方向与外挂拆小一致 | 已遵循 |

## 四、结论

1. **MoE 不是终点**：MoD（深度）、TTT（推理时学习）、EMO（document 路由）、SSM 混合都在分流。但**没有一条路线否定"应用层编排"的价值**——恰恰相反：架构越多越碎，黑盒编排层的价值越大（架构不可知的应用侧优化）。
2. **外挂系列获得三层实现谱系**：prompt 级（我们）→ 权重级推理（TTT）→ 权重级训练（MoE 原生）。三层是同一思想的递进，未来 PPBExt-Cache/Decide 可以随模型开放度下沉到 TTT 层（In-Place TTT 的 Qwen3-4B 实验给了现成的对照基座）。
3. **PPBExt-Knowledge 获得架构级先例**：TTT-E2E 的双轨存储（static+dynamic MLP）是"冻结基座+附加模块"在 transformer 内部的实现——学习外挂的思想在权重级已有独立验证，引用价值高。
